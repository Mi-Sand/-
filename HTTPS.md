# Работа по HTTPS

Сейчас система работает по обычному HTTP: пароли и данные идут по сети
предприятия открытым текстом.

## Нужно ли это вам

**Внутри предприятия — можно оставить как есть.** Чтобы прочитать
пароль кладовщика, посторонний должен уже находиться в вашей сети со
своим устройством. Если сеть закрыта и система наружу не выставлена,
шифрование мало что добавляет, а хлопот прибавляет.

**Переходить на HTTPS стоит, если:**

- система открыта из интернета — тогда обязательно;
- в сети бывают чужие устройства: гости с ноутбуками, открытый Wi-Fi,
  подрядчики;
- этого требует внутренний порядок предприятия или проверяющие.

Переход занимает примерно полчаса и делается один раз.

---

## Что для этого нужно

1. **nginx** — веб-сервер, который встанет перед системой и возьмёт на
   себя шифрование. Скачивается с nginx.org, распаковывается в папку,
   установки не требует.
2. **Сертификат** — выпускается своим же скриптом, за него не платят.
3. **Три строки в `.env`.**

Купленный сертификат здесь не нужен и чаще всего невозможен: их выдают
на имена в интернете, а `sklad.leko.local` существует только внутри
предприятия.

---

## Порядок

### 1. Выпустить сертификат

```powershell
cd D:\warehouse_project\deploy\windows
.\СДЕЛАТЬ-СЕРТИФИКАТ.ps1 -Name sklad.leko.local -Address 192.168.1.50
```

Запускать от имени администратора. Скрипт создаст три файла в
`deploy\nginx`:

| Файл | Для чего |
|---|---|
| `sklad.crt` | сертификат для nginx |
| `sklad.key` | ключ для nginx — **никому не показывать** |
| `sklad-для-сотрудников.crt` | ставится на рабочие места |

Имя в сертификате должно совпадать с адресом, который сотрудники
набирают в браузере. Если открывают по адресу вида `192.168.1.50` —
укажите его в `-Address`.

### 2. Настроить nginx

Возьмите за основу `deploy\nginx\warehouse-https.conf`. Заменить нужно
три вещи: имя сервера, пути к сертификату и пути к папкам `staticfiles`
и `media`.

Проверить настройку до запуска:

```powershell
nginx -t -c D:\warehouse_project\deploy\nginx\warehouse-https.conf
```

Запустить:

```powershell
nginx -c D:\warehouse_project\deploy\nginx\warehouse-https.conf
```

### 3. Включить HTTPS в системе

В `.env`:

```
USE_HTTPS=True
CSRF_TRUSTED_ORIGINS=https://sklad.leko.local,https://192.168.1.50
```

**Адреса должны совпадать в точности,** вместе с портом, если он не
443. `https://sklad.leko.local` и `https://192.168.1.50` — разные
адреса, и оба нужно перечислить, если сотрудники пользуются обоими.
Иначе вход отвечает «подделка запроса»: это самая частая ошибка при
переходе.

Что включается вместе с `USE_HTTPS=True`:

- обращение по http перенаправляется на https;
- куки сессии и защиты от подделки помечаются «только по защищённому
  соединению» — это главное, ради чего всё делается;
- браузеру сообщается, что на этот адрес полгода ходить только по
  https.

### 4. Проверить

```powershell
cd D:\warehouse_project
venv\Scripts\python.exe manage.py checksetup
```

Проверка скажет, согласованы ли настройки, и предупредит о забытых
адресах.

Потом откройте систему в браузере и войдите. Если вход проходит и в
адресной строке замок — готово.

### 5. Убрать предупреждение браузера

Сертификат выпущен предприятием, а не признанным удостоверяющим
центром, поэтому браузер честно говорит: «этому сайту доверять нельзя».

Нажимать каждый день «всё равно продолжить» — плохая привычка: однажды
так же нажмут на настоящей подмене. Поставьте сертификат на рабочие
места:

1. Скопируйте `sklad-для-сотрудников.crt` на компьютер сотрудника.
2. Двойное нажатие → **Установить сертификат**.
3. Расположение: **Локальный компьютер**.
4. **Поместить все сертификаты в следующее хранилище** → **Обзор** →
   **Доверенные корневые центры сертификации**.
5. Закрыть и заново открыть браузер.

Предупреждение пропадёт. В домене это же раздаётся групповой политикой
разом на все машины.

## Если что-то пошло не так

**«Подделка запроса» при входе.** Не перечислен адрес в
`CSRF_TRUSTED_ORIGINS` или перечислен не тот: с http вместо https, без
порта, по имени вместо адреса.

**Браузер ходит по кругу и говорит «слишком много перенаправлений».**
nginx не передаёт заголовок `X-Forwarded-Proto https` — система считает
соединение незащищённым и отправляет браузер на https снова. Строка
есть в образце настройки.

**Система вообще перестала открываться после `USE_HTTPS=True`.**
Вероятно, nginx не запущен или слушает не тот порт. Поставьте обратно
`USE_HTTPS=False`, убедитесь, что система работает по http, и
разбирайтесь с nginx отдельно.

**Забыли пароль от ключа, потеряли файлы.** Ничего страшного:
выпустите сертификат заново тем же скриптом и переустановите его на
рабочие места. Данные это не затрагивает.

---

## Проверено

Порядок из этого файла проверен целиком: система поднята за nginx с
таким сертификатом, обращение по http перенаправляется на https, вход
проходит, куки сессии и защиты от подделки помечены «только по
защищённому соединению», страницы и витрина открываются, в браузере
ошибок нет.
