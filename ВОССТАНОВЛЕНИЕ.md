# Что делать, если система не работает

Порядок восстановления складского учёта ООО Фирма «ЛЕКО».

Держите эту страницу распечатанной рядом с компьютером. Она нужна
ровно тогда, когда компьютера может не быть.

Всё описанное здесь проверено на деле: база портилась намеренно и
разворачивалась заново.

---

## Сначала — что случилось

| Что видно | Куда идти |
|---|---|
| Система не открывается, окно сервера закрыто | [Сервер не запущен](#сервер-не-запущен) |
| «database disk image is malformed», страницы с ошибкой | [База испорчена](#база-испорчена) |
| Пропали документы, остатки не те | [Данные потеряны или испорчены](#данные-потеряны-или-испорчены) |
| Компьютер не включается, диск сгорел, машину украли | [Компьютера нет](#компьютера-нет) |

Во всех случаях, кроме последнего, восстановление занимает **минуты**.
В последнем — **час-полтора**, и почти всё это время идёт установка
Python.

---

## Сервер не запущен

Самый частый случай, и это не поломка: кто-то закрыл окно.

```powershell
cd D:\warehouse_project
.\venv\Scripts\Activate.ps1
python manage.py runserver
```

Затем откройте адрес системы в браузере.

Если окно открывается и сразу закрывается, запустите проверку — она
скажет, что не так:

```powershell
cd D:\warehouse_project
venv\Scripts\python.exe manage.py checksetup
```

## База испорчена

Признак: страницы отвечают ошибкой, в окне сервера — `database disk
image is malformed` или `database is locked` без конца.

**1. Закройте окно с сервером.** Восстанавливать при работающей
системе нельзя: она допишет своё поверх развёрнутой копии.

**2. Разверните последнюю копию:**

```powershell
cd D:\warehouse_project\deploy\windows
.\ВОССТАНОВИТЬ.ps1 -In D:\Копии\Склад
```

Без `-In` копия берётся из папки `backups` внутри программы.

Команда сама:

- выберет самую свежую копию;
- **проверит её до подмены** — битую разворачивать не станет;
- отложит нынешнюю базу рядом под именем
  `db.sqlite3.до-восстановления-…`;
- вернёт базу и фотографии;
- скажет, сколько записей вернулось.

**3. Проверьте и запускайте:**

```powershell
cd D:\warehouse_project
venv\Scripts\python.exe manage.py checksetup
```

Запустите систему, откройте остатки, приход и отчёты. Убедившись, что
всё на месте, удалите файл `db.sqlite3.до-восстановления-…`.

**Что теряется.** Работа, сделанная после последней копии. Копии
снимаются ночью, значит потерян будет текущий день. Что было проведено
за день, восстанавливают по бумагам — накладным и приходным
документам.

Если самая свежая копия оказалась битой, возьмите предыдущую:

```powershell
.\ВОССТАНОВИТЬ.ps1 -From D:\Копии\Склад\2026-08-10_23-30-00
```

## Данные потеряны или испорчены

Здесь спешить не нужно: система работает, база цела, но данные не те —
кто-то удалил документ, испортил остатки, провёл лишнее.

**Сначала посмотрите журнал действий** — раздел «Журнал действий» в
меню. Там видно, кто и когда менял запись, и какие значения были до
правки. Часто этого достаточно, чтобы вернуть всё руками, ничего не
восстанавливая.

Разворачивать копию стоит, только если потеряно много. Помните: копия
вернёт **всю** базу на состояние на ночь, а не одну испорченную
запись. Работа всех сотрудников за день пропадёт.

## Компьютера нет

Диск сгорел, машина не включается или её украли. Нужен другой
компьютер с Windows.

Понадобится: **копия** (с внешнего диска или из сетевой папки) и
**полтора часа**.

### 1. Поставьте Python

Скачайте с python.org (версия 3.11 или новее). При установке отметьте
**«Add python.exe to PATH»** — без этой галочки ничего дальше не
заработает.

### 2. Возьмите программу

Если есть доступ к репозиторию:

```powershell
git clone <адрес репозитория> D:\warehouse_project
```

Если нет — распакуйте архив с программой в `D:\warehouse_project`.
Программа есть и внутри любой копии? Нет: копия содержит **данные**, а
не программу. Держите архив с программой рядом с копиями — это тот
случай, когда лишний файл на диске стоит целого дня.

### 3. Поставьте окружение

```powershell
cd D:\warehouse_project
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt
```

Это самый долгий шаг — несколько минут.

### 4. Верните настройки

Файл `.env` лежит **внутри копии**. Скопируйте его в папку программы:

```powershell
Copy-Item D:\Копии\Склад\2026-08-11_23-30-00\.env D:\warehouse_project\.env
```

В нём секретный ключ и параметры этой установки. Без него система
запустится, но сессии сотрудников придётся заводить заново, а часть
настроек — вспоминать.

### 5. Создайте таблицы и разверните копию

```powershell
venv\Scripts\python.exe manage.py migrate
cd deploy\windows
.\ВОССТАНОВИТЬ.ps1 -In D:\Копии\Склад
```

### 6. Проверьте

```powershell
cd D:\warehouse_project
venv\Scripts\python.exe manage.py checksetup
```

Запустите систему и откройте несколько рабочих страниц.

### 7. Настройте копии заново

На новом компьютере задания в планировщике нет:

```powershell
cd deploy\windows
.\НАСТРОИТЬ-КОПИИ.ps1 -To D:\Копии\Склад
```

Этот шаг забывают чаще всего. Система работает, все довольны — а копий
снова нет.

## Если база на PostgreSQL

Порядок другой: восстановление идёт средствами самой базы.

```powershell
dropdb -U postgres warehouse_db
createdb -U postgres -O warehouse_user warehouse_db
psql -U warehouse_user -d warehouse_db -f D:\Копии\Склад\2026-08-11_23-30-00\db.sql
```

Точные команды записаны в файле `ЧТО-ЭТО.txt` внутри каждой копии.
Фотографии и `.env` возвращаются оттуда же, обычным копированием.

## Чтобы этот день прошёл легче

**Проверяйте восстановление, не дожидаясь беды.** Раз в квартал
разверните копию в отдельной папке и посмотрите, что данные на месте.
Копия, которую ни разу не разворачивали, — это надежда, а не гарантия.

**Держите копии не на том же диске.** Копия рядом с базой не спасает
от отказа диска — а это и есть главный случай, ради которого копии
делают. Внешний диск или сетевая папка:

```powershell
.\НАСТРОИТЬ-КОПИИ.ps1 -To D:\Копии\Склад
```

**Держите рядом с копиями архив с программой.** Данные без программы
не работают.

**Второй компьютер про запас.** Если простой в день — это дорого,
поставьте систему на второй компьютер и не запускайте. Тогда
восстановление сведётся к шагу 5: развернуть копию и запустить. Это
двадцать минут вместо полутора часов.

**Проверьте, что копии вообще снимаются.** Раз в месяц:

```powershell
venv\Scripts\python.exe manage.py checksetup
```

Проверка скажет, когда снята последняя копия, и предупредит, если
последней больше недели.
