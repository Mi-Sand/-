# Доступ к системе с других компьютеров в сети

Эта инструкция — как открыть доступ к складской системе для других
компьютеров в той же локальной сети (например, чтобы кладовщик и
экономист работали каждый со своего ПК).

## Как это работает

Сервер запускается на одном компьютере (назовём его «сервер»), а
остальные заходят в него через браузер по его IP-адресу. Все данные
хранятся в одной базе на сервере — все видят одно и то же.

---

## Шаг 1. Узнать IP-адрес компьютера-сервера

На том ПК, где запускается сервер, откройте PowerShell и выполните:

```powershell
ipconfig
```

Найдите строку **«IPv4-адрес»** в разделе вашего активного подключения
(Ethernet или беспроводная сеть). Будет что-то вроде:

```
IPv4-адрес . . . . . . . . . . . : 192.168.1.50
```

Запомните этот адрес — например `192.168.1.50`. Именно по нему другие
компьютеры будут заходить в систему.

> Совет: локальные адреса обычно начинаются на `192.168.` или `10.`
> Если адресов несколько — берите тот, что в подсети вашего роутера
> (чаще всего `192.168.x.x`).

---

## Шаг 2. Запустить сервер с доступом по сети

Обычная команда `runserver` слушает только сам компьютер. Чтобы принять
подключения извне, добавьте `0.0.0.0:8000`:

```powershell
python manage.py runserver 0.0.0.0:8000
```

`0.0.0.0` означает «принимать подключения на всех сетевых интерфейсах».
Порт `8000` — стандартный (можно оставить как есть).

Сервер запущен. **Не закрывайте это окно PowerShell** — пока оно
открыто, сервер работает.

---

## Шаг 3. Разрешить подключения в брандмауэре Windows

По умолчанию брандмауэр Windows блокирует входящие подключения. Нужно
разрешить порт 8000. Откройте PowerShell **от имени администратора**
(правой кнопкой на «PowerShell» → «Запуск от имени администратора») и
выполните одной командой:

```powershell
New-NetFirewallRule -DisplayName "Warehouse 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
```

Готово — Windows теперь пропускает подключения на порт 8000.

> Если команда выдала ошибку про права — значит PowerShell запущен не от
> администратора. Закройте и откройте заново через «Запуск от имени
> администратора».

Альтернатива через графический интерфейс: при первом запуске
`runserver 0.0.0.0:8000` Windows может сам показать окно «Разрешить
доступ?» — нажмите «Разрешить доступ» и поставьте галочки для частных
сетей.

---

## Шаг 4. Зайти с другого компьютера

На любом другом компьютере в той же сети (подключённом к тому же роутеру
/ Wi-Fi) откройте браузер и введите в адресной строке IP сервера и порт:

```
http://192.168.1.50:8000
```

(подставьте свой адрес из Шага 1)

Откроется та же система входа. Войдите под своим логином — и работайте.

---

## Создание отдельных пользователей

Чтобы у каждого сотрудника был свой вход, создайте им учётные записи.
На сервере, в новом окне PowerShell (с активированным venv):

```powershell
cd D:\warehouse_project\warehouse_project
.\venv\Scripts\Activate.ps1
python manage.py createsuperuser
```

Либо, если не нужны полные права администратора, заводите обычных
пользователей через админку: `http://192.168.1.50:8000/admin/` →
раздел «Пользователи» → «Добавить».

Роли (кладовщик, экономист, менеджер) можно назначить там же, в поле
«Роль» пользователя.

## Частые проблемы

### «Не удаётся получить доступ к сайту» с другого ПК

1. **Проверьте, что оба компьютера в одной сети** — подключены к одному
   роутеру/Wi-Fi. Из другого ПК выполните в PowerShell:
   ```powershell
   ping 192.168.1.50
   ```
   Если идут ответы — сеть в порядке. Если «превышен интервал ожидания» —
   компьютеры в разных сетях или мешает роутер.

2. **Проверьте, что сервер запущен именно с `0.0.0.0:8000`**, а не просто
   `runserver`. В окне сервера должна быть строка вида:
   ```
   Starting development server at http://0.0.0.0:8000/
   ```

3. **Проверьте брандмауэр** (Шаг 3) — правило должно быть создано.

4. **Антивирус** со своим файрволом может блокировать — временно
   отключите его файрвол для проверки.

### Работает по IP на самом сервере, но не с других ПК

Почти всегда это брандмауэр (Шаг 3) или антивирус. Убедитесь, что
правило создано, и что вы используете IP-адрес, а не `localhost`
(localhost работает только на самом сервере).

### IP-адрес меняется после перезагрузки

По умолчанию роутер выдаёт адреса динамически, и после перезагрузки
адрес сервера может смениться. Чтобы закрепить постоянный адрес,
попросите закрепить IP за этим компьютером в настройках роутера
(«резервирование DHCP» / «static lease» по MAC-адресу) — или обратитесь
к вашему сисадмину.

---

## Важно про безопасность

Этот режим (`DEBUG=True`, `runserver`) предназначен для локальной сети
предприятия, а не для публикации в интернет. Не открывайте порт 8000
наружу через роутер (проброс портов) без настройки настоящего боевого
режима — для этого используется связка с nginx и HTTPS (см. `DOCKER.md`).
Внутри защищённой локальной сети предприятия описанного выше достаточно.

## Итоговая шпаргалка (на сервере)

```powershell
# 1. Узнать IP
ipconfig                      # ищем IPv4-адрес, напр. 192.168.1.50

# 2. Один раз — разрешить порт в брандмауэре (PowerShell от админа)
New-NetFirewallRule -DisplayName "Warehouse 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow

# 3. Запуск сервера (обычный PowerShell, в папке проекта, venv активен)
python manage.py runserver 0.0.0.0:8000

# 4. С других ПК заходить в браузере:
#    http://192.168.1.50:8000
```
