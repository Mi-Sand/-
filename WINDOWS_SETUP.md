# Установка и запуск на Windows

Это руководство — Windows-версия README.md. Весь Python/Django-код в проекте
кроссплатформенный (использует `pathlib`, работает одинаково на Windows,
Linux и macOS) — отличаются только команды в терминале.

## Требования

- **Python 3.10 и новее** (проверено вплоть до 3.14) — скачать с https://www.python.org/downloads/
  При установке **обязательно** отметьте галочку **«Add python.exe to PATH»**
  на первом экране инсталлятора — без неё команда `python` не будет найдена.
- **PowerShell** (уже есть в Windows 10/11) — рекомендуется вместо
  Командной строки (cmd), команды ниже даны для PowerShell.
- Docker Desktop — опционально, если хотите запускать через Docker.

### Проверка, что Python установлен правильно

Откройте **PowerShell** (Пуск → введите «PowerShell» → Enter) и выполните:

```powershell
python --version
```

Должно вывести что-то вроде `Python 3.11.5`. Если вместо этого:
- открылся **Microsoft Store** — Python не установлен, App Execution Alias
  перехватывает команду. Установите Python с python.org, либо отключите
  алиас: **Параметры → Приложения → Дополнительные параметры приложений →
  Псевдонимы выполнения приложений** → выключите оба переключателя python.
- ошибка **«python не является внутренней или внешней командой»** —
  Python не добавлен в PATH. Переустановите с галочкой «Add to PATH», или
  используйте `py` вместо `python` (лаунчер `py.exe` ставится отдельно и
  часто работает, даже если PATH не настроен для `python.exe`).

## Быстрый старт

### 1. Распаковать архив

Если Проводник Windows не открывает `.tar.gz` через «Извлечь всё» (эта
кнопка понимает только `.zip`) — используйте один из вариантов:

**Вариант А — если у вас `warehouse_project.zip`:**
Просто щёлкните правой кнопкой → «Извлечь всё...».

**Вариант Б — если только `warehouse_project.tar.gz`:**
В PowerShell (начиная с Windows 10 версии 1803+ `tar` встроен):

```powershell
tar -xzf warehouse_project.tar.gz
```

### 2. Перейти в папку проекта

```powershell
cd warehouse_project
```

### 3. Создать виртуальное окружение

```powershell
python -m venv venv
```

### 4. Активировать виртуальное окружение

```powershell
.\venv\Scripts\Activate.ps1
```

**Если появилась ошибка о запрете выполнения скриптов** («...cannot be
loaded because running scripts is disabled on this system»), выполните
один раз (нужны права на изменение политики для текущего пользователя,
администратор не требуется):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Подтвердите `Y`, затем повторите шаг 4. Строка приглашения должна
измениться на `(venv) PS ...>` — это значит, что окружение активно.

### 5. Установить зависимости

```powershell
pip install -r requirements.txt
```

### 6. Создать базу данных

```powershell
python manage.py migrate
```

Миграции лежат в репозитории, `makemigrations` запускать не нужно —
`migrate` создаст все таблицы сам.

### 7. Создать администратора

```powershell
python manage.py createsuperuser
```

Введите имя пользователя, email (можно пропустить — Enter) и пароль.
Пароль не отображается при вводе — это нормально, просто печатайте и
нажимайте Enter.

### 8. Запустить сервер

```powershell
python manage.py runserver
```

**Если Windows Defender Firewall покажет всплывающее окно** «Разрешить
доступ Python через брандмауэр?» — нажмите **«Разрешить доступ»**
(нужно для работы сервера в локальной сети; для доступа только с этого же
компьютера через `127.0.0.1` можно нажать «Отмена», сервер всё равно
заработает).

### 9. Открыть в браузере

```
http://127.0.0.1:8000
```

Остановить сервер: `Ctrl+C` в окне PowerShell.

Проверить, что Docker работает:

```powershell
docker --version
docker-compose --version
```

## Использование API из PowerShell

В примерах `API_EXAMPLES.md` команды даны для `curl` в стиле Linux/macOS.
В PowerShell есть важный нюанс: команда `curl` там — это **псевдоним**
для `Invoke-WebRequest`, который принимает параметры иначе, чем настоящий
curl. Есть два способа получить те же результаты:

### Способ 1 — вызвать настоящий curl.exe напрямую

Начиная с Windows 10 версии 1803, в системе есть реальный `curl.exe`.
Чтобы обратиться именно к нему (в обход алиаса PowerShell), пишите
`curl.exe` вместо `curl`:

```powershell
curl.exe -u admin:admin123 http://127.0.0.1:8000/api/materials/
```

### Способ 2 — нативные команды PowerShell

```powershell
# Список материалов
$cred = Get-Credential   # введите admin / пароль в окне
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/materials/" -Credential $cred

# Создание материала
$body = @{
    name = "Хлопчатобумажная ткань"
    unit = "m"
    category = "textile"
    reorder_point = 50.0
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/materials/" `
    -Method Post -Credential $cred `
    -ContentType "application/json; charset=utf-8" `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($body))

# Проведение приходного документа
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/inbound-documents/1/process/" `
    -Method Post -Credential $cred -ContentType "application/json" -Body "{}"
```

**Примечание про кириллицу:** при отправке текста на русском языке через
`Invoke-RestMethod` рекомендуется явно кодировать тело запроса в UTF-8
байты (как показано выше через `[System.Text.Encoding]::UTF8.GetBytes(...)`),
иначе PowerShell 5.1 может отправить его в неверной кодировке.

## Резервные копии

Копия — единственное, что отделяет от потери всего учёта при отказе
диска. База лежит в одном файле на одном компьютере.

### Настроить один раз

```powershell
cd D:\warehouse_project\deploy\windows
.\НАСТРОИТЬ-КОПИИ.ps1 -To D:\Копии\Склад
```

Скрипт заводит задание в планировщике Windows: каждую ночь в 23:30
снимается копия базы и настроек. Права администратора не нужны.

Перед созданием задания копия снимается пробно. Если не получилось,
задание не создаётся: заводить дело, которое каждую ночь молча падает,
хуже, чем не заводить вовсе.

**Указывайте другой диск или сетевую папку.** Копия рядом с базой не
спасёт от отказа диска — а ради него всё и затевается. Без `-To` копии
лягут в папку `backups` рядом с программой, и скрипт об этом
предупредит.

Полезные ключи:

```powershell
.\НАСТРОИТЬ-КОПИИ.ps1 -At 02:00 -Keep 60   # время и срок хранения
.\НАСТРОИТЬ-КОПИИ.ps1 -Remove              # убрать задание
```

### Снять копию сейчас

```powershell
.\backup.ps1
.\backup.ps1 -To D:\Копии\Склад -NoMedia
```

То же самое делает `python manage.py backup` из папки программы.

### Что внутри копии

| | |
|---|---|
| `db.sqlite3` | база целиком: остатки, документы, история, заказы |
| `media\` | фотографии товаров |
| `.env` | настройки этой установки |
| `ЧТО-ЭТО.txt` | что за папка и как из неё восстановиться |

Копия базы снимается средством самой SQLite, а не копированием файла.
Обычная копия «на ходу» может остаться без последних проведённых
документов: часть свежих записей лежит в служебном журнале рядом с
базой. Ошибки при этом не будет — потеря обнаружится только при
восстановлении.

**Копия проверяется сразу после создания:** открывается и сверяется с
базой по числу записей в каждой таблице. Это не формальность.
Копия, потерявшая часть записей, остаётся исправным файлом — встроенная
проверка SQLite скажет «всё в порядке». Поймать такую может только
сверка с базой.

Ежедневные копии снимаются без фотографий: они занимают больше всего
места, а меняются редко. Полная копия с фотографиями делается при
обновлении системы и при ручном запуске `backup.ps1`.

### Восстановление

```powershell
# 1. Остановить систему — Ctrl+C в окне сервера

# 2. Вернуть базу из нужной копии
Copy-Item D:\Копии\Склад\2026-08-07_23-30\db.sqlite3 `
          D:\warehouse_project\db.sqlite3 -Force

# 3. При необходимости — фотографии и настройки оттуда же

# 4. Проверить и запустить
cd D:\warehouse_project
.\venv\Scripts\Activate.ps1
python manage.py checksetup
python manage.py runserver 0.0.0.0:8000
```

Тот же порядок записан в файле `ЧТО-ЭТО.txt` внутри каждой копии — на
случай, если эта инструкция под рукой не окажется.

**Проверьте восстановление, не дожидаясь беды.** Разверните копию в
отдельную папку и убедитесь, что система на ней запускается. Копия, из
которой ни разу не восстанавливались, — это надежда, а не резерв.

## Обновление работающей системы

Обновляется только код. База, фотографии товаров и файл настроек в
репозитории не хранятся и остаются на месте.

**Никогда не удаляйте папку и не распаковывайте новую версию на чистое
место** — так теряются база и фотографии. Обновлять нужно поверх.

| Останется | Заменится |
|---|---|
| `db.sqlite3` — вся база | код приложения |
| `media\` — фотографии товаров | `templates\` — интерфейс |
| `.env` — ваши настройки | `requirements.txt` |
| `venv\` — окружение | миграции |

### Одной командой

Закройте окно с работающим сервером, затем в папке `deploy\windows`
щёлкните по **`ОБНОВИТЬ.bat`**.

Скрипт делает всё по порядку: снимает копию базы, фотографий и настроек,
получает новый код, обновляет библиотеки, применяет миграции, собирает
оформление и проверяет результат.

**Если проверка не прошла, база автоматически возвращается из копии,**
снятой в начале. Код при этом остаётся обновлённым — скрипт не откатывает
его сам, чтобы не потерять ваши правки, если они были, но подсказывает,
как это сделать.

**Если в папке программы что-то правили руками**, обновление это заметит
и отложит правку в сторону, чтобы получить новый код:

```
в папке программы изменены файлы (1 шт.) — откладываю их
   M HTTPS.md
вернуть их можно командой: git stash pop
```

Правка не пропадает: `git stash list` покажет отложенное, `git stash pop`
вернёт. Настроек (`.env`), базы и фотографий это не касается — они под
git не числятся и остаются нетронутыми.

Полезные ключи:

```powershell
.\ОБНОВИТЬ.bat -SkipMedia   # не копировать фотографии (когда их много)
.\ОБНОВИТЬ.bat -NoPull      # код уже распакован вручную, только доделать
```

Второй ключ нужен, если обновляетесь не через git, а распаковкой архива:
сначала распакуйте файлы поверх папки, потом запустите с `-NoPull`. Хотя
без git скрипт и сам это поймёт и шаг с получением кода пропустит.

**Запускайте через `ОБНОВИТЬ.bat`, а не `.\update.ps1` напрямую.** Windows
по умолчанию не даёт запускать сценарии PowerShell — прямой запуск
упирается в «файл не имеет цифровой подписи». Файл `.bat` обходит это
штатным способом, разово и только для себя. Если нужен именно прямой
вызов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\update.ps1 -NoPull
```

### Вручную

Если хочется контролировать каждый шаг:

```powershell
cd D:\warehouse_project
.\venv\Scripts\Activate.ps1

# 1. Остановить систему — Ctrl+C в окне сервера

# 2. Копия. Именно до всего остального
mkdir backups\ручная -Force
python -c "import sqlite3; c=sqlite3.connect('db.sqlite3'); c.execute('VACUUM INTO ?', ('backups/ручная/db.sqlite3',)); c.close()"
Copy-Item media backups\ручная\media -Recurse -Force
Copy-Item .env  backups\ручная\.env

# 3. Код
git pull

# 4. Библиотеки
pip install -r requirements.txt --upgrade

# 5. База
python manage.py migrate

# 6. Оформление
python manage.py collectstatic --noinput

# 7. Проверка
python manage.py checksetup
```

Копию снимайте **при остановленной системе**. SQLite держит часть свежих
записей в служебном журнале рядом с базой, поэтому копия «на ходу» может
оказаться без последних проведённых документов — молча, без ошибки.
Команда с `VACUUM INTO` выше обходит это: она снимает согласованную копию
средствами самой SQLite.

### После обновления

`checksetup` не формальность: он ловит именно то, что ломается при
обновлении — неприменённые миграции, несобранную статику, несовместимые
версии библиотек.

Но он не увидит, если поехала вёрстка. Откройте руками две-три рабочие
страницы: приход, отчёты, витрину.

### Чего не делать

**Не обновляйте библиотеки поодиночке.** Команда вида
`pip install django-filter --upgrade` без ограничений подтягивает
несовместимые версии — именно так система однажды перестала запускаться.
Только `pip install -r requirements.txt --upgrade`: в этом файле границы
версий, проверенные на тестах.

**Не пропускайте `migrate`.** Симптом — страница падает с ошибкой про
несуществующий столбец. Выглядит как поломка кода, а на деле база просто
отстала от него.

### Если что-то сломалось

Обратных миграций в проекте нет, поэтому откат — это восстановление
копии, а не «отменить migrate»:

```powershell
# остановить систему, затем
Copy-Item backups\2026-08-06_12-30\db.sqlite3 db.sqlite3 -Force
git log --oneline -5                 # найти предыдущую версию
git checkout <номер-коммита>
pip install -r requirements.txt --upgrade
python manage.py checksetup
```

Копии лежат в папке `backups`, каждая в своей подпапке с датой и временем.
Удалять их можно, когда убедитесь, что обновление прижилось.

## Если система не работает

Порядок восстановления вынесен в отдельный файл: **ВОССТАНОВЛЕНИЕ.md**.
Там разобраны четыре случая — сервер не запущен, база испорчена, данные
потеряны, компьютера нет — и для каждого записано, что делать и сколько
это займёт.

Коротко, для случая «база испорчена»:

```powershell
cd D:\warehouse_project\deploy\windows
.\ВОССТАНОВИТЬ.ps1 -In D:\Копии\Склад
```

Команда сама возьмёт свежую копию, проверит её **до** подмены, отложит
нынешнюю базу в сторону и скажет, сколько записей вернулось.

Файл ВОССТАНОВЛЕНИЕ.md стоит распечатать и держать рядом с
компьютером: он нужен ровно тогда, когда компьютера может не быть.

## Шифрование соединения (HTTPS)

Сейчас система работает по обычному HTTP: пароли идут по сети
предприятия открытым текстом. Внутри закрытой сети это приемлемо —
чтобы их прочитать, посторонний должен уже находиться в вашей сети со
своим устройством.

Переходить на HTTPS стоит, если система открыта из интернета, если в
сети бывают чужие устройства или этого требует внутренний порядок.

Всё для перехода готово и проверено; занимает он около получаса:

```powershell
cd D:\warehouse_project\deploy\windows
.\СДЕЛАТЬ-СЕРТИФИКАТ.ps1 -Name sklad.leko.local -Address 192.168.1.50
```

Дальше — настройка nginx: её делает `deploy\windows\НАСТРОИТЬ-NGINX.ps1`
и две строки в `.env`. Порядок целиком, вместе с разбором частых ошибок,
— в **HTTPS.md**.

Самая частая ошибка при переходе: забыть перечислить адреса в
`CSRF_TRUSTED_ORIGINS`. Тогда вход отвечает «подделка запроса».
Проверка `checksetup` предупреждает об этом заранее.

## Почта: сводка вместо потока писем

Система умеет предупреждать: остаток упал ниже минимума,
инвентаризация нашла недостачу. Но по умолчанию письма печатались в
окно сервера и никуда не уходили — предупреждения формально были, а
фактически их никто не видел.

### 1. Настроить отправку

Порядок — в `SMTP_SETUP.md`: несколько строк в `.env` с адресом
почтового сервера, именем и паролем. Для Яндекса и Gmail нужен не
пароль от почты, а отдельный пароль приложения.

### 2. Убедиться, что письма доходят

```powershell
cd D:\warehouse_project
venv\Scripts\python.exe manage.py testmail
```

Команда покажет нынешние настройки (пароль не покажет) и отправит одно
письмо. Если сервер откажет, она объяснит причину по-русски — не тот
порт, не то шифрование, не подошёл пароль.

Проверьте и папку «Спам»: письма от новых отправителей часто попадают
туда.

### 3. Поставить ежедневную сводку

```powershell
cd D:\warehouse_project\deploy\windows
.\НАСТРОИТЬ-СВОДКУ.ps1
```

По умолчанию письмо приходит в 08:00 — чтобы ждало в ящике к началу
рабочего дня. Другое время и другой адрес:

```powershell
.\НАСТРОИТЬ-СВОДКУ.ps1 -At 07:30 -To nachalnik@example.ru
```

Посмотреть сводку прямо сейчас, ничего не отправляя:

```powershell
venv\Scripts\python.exe manage.py dailysummary --dry-run
```

### Что в сводке

Сначала то, из-за чего письмо стоит открывать:

- остатки ниже минимума (по сумме всех складов, а не по каждому);
- партии с истекающим сроком годности;
- заказы, которые никто не подтвердил дольше суток;
- давно ли снимали резервную копию.

Потом — что происходило за сутки: сколько проведено приходов и
расходов, сколько выпущено продукции, сколько заказов пришло и
отгружено.

Если тревожиться не о чем, письмо всё равно приходит: «всё спокойно» —
это тоже сведения, а молчание можно спутать со сломанной рассылкой.

### Письма на каждое событие

Раньше письмо уходило при каждом падении остатка ниже минимума. Остаток
пересчитывается при каждом проведении документа, и при десятке
материалов набегал десяток писем в день — такой ящик перестают читать.
Теперь низкие остатки перечислены в сводке, а отдельные письма
выключены.

Кому они всё же нужны — включаются в `.env`:

```
NOTIFY_LOW_STOCK_INSTANTLY=True
```

Письмо о недостачах по итогам инвентаризации осталось мгновенным:
инвентаризация бывает редко, и ждать до утра тут нечего.

## Корзина удалённых документов

Удалённый непроведённый документ не пропадает — он попадает в корзину,
раздел «Корзина» в боковом меню. Оттуда его возвращают одним нажатием
вместе со строками. В списках, отчётах и выгрузках такой документ не
показывается.

Через месяц корзина чистится. Само это не происходит: поставьте задание
рядом с ночным снятием копий.

```powershell
cd D:\warehouse_project
.\venv\Scripts\python.exe manage.py purgetrash --yes --quiet
```

Задание в планировщике — по образцу задания на копии (см. раздел
«Резервные копии»), время лучше взять на полчаса позже.

Проверить, что будет вычищено, ничего не удаляя:

```powershell
.\venv\Scripts\python.exe manage.py purgetrash
```

Без ключа `--yes` команда только перечисляет. Срок хранения меняется в
`.env`:

```
TRASH_KEEP_DAYS=30
```

**Номер документа освобождается сразу при удалении.** Пока документ
лежит в корзине, завести новый с тем же номером можно; при возврате из
корзины система скажет, если номер уже занят, — тогда сперва
переименуйте занявший.

## Штрихкоды и этикетки

У материалов и продукции есть поле «Штрихкод». Заполнять его руками не
нужно: поставьте курсор в поле и поднесите сканер — он «печатает» код
сам и жмёт ввод. Тот же приём работает в поле поиска: сканер подносят к
коробке, и позиция находится сразу.

Этикетки печатаются из списка — кнопка с принтером в строке позиции.
Система спросит, сколько этикеток нужно, и откроет лист в отдельной
вкладке; печать обычная, Ctrl+P. Лист размечен под наклейку шириной
около 62 мм, на А4 помещается три в ряд.

Позициям без своего штрихкода система выдаёт внутренний номер вида
`MAT00000012`. Покупать диапазон номеров у регистратора нужно только
тому, кто отдаёт товар в чужие магазины; для учёта на своём складе
внутреннего номера достаточно.

Штрихкод берёт цифры и латиницу — русские буквы не берёт ни один
штрихкод. Поэтому в код идёт артикул или внутренний номер, а название
печатается на этикетке рядом словами.

## Пределы для заказов с витрины

Витрина открыта без входа — так и задумано. Но товар при оформлении
заказа уходит в резерв: физически он на складе, но обещан покупателю и
на витрине больше не показывается. Без пределов один человек за минуту
оформлял сотню заказов, и настоящие покупатели видели «нет в наличии».

### Что ограничено

| Предел | По умолчанию |
|---|---|
| Заказов с одного компьютера за час | 5 |
| Заказов на один номер телефона за час | 3 |
| Через сколько часов снимается резерв с неподтверждённого заказа | 24 |

Значения правятся в `warehouse_config/settings.py`, раздел
`SHOP_ORDER_LIMITS`. Ноль отключает предел.

Отменённые заказы в счёт не идут: человек мог ошибиться, отменить и
оформить заново. Заказы, заведённые сотрудником в системе, под предел
не попадают вовсе.

Покупатель, упёршийся в предел, видит не «ошибка», а объяснение с
предложением позвонить.

### Возврат товара на витрину

Заказ, который никто не подтвердил за сутки, отменяется, и товар
возвращается покупателям. Причина записывается в сам заказ — через
месяц никто не вспомнит, почему он отменён.

Настроить, чтобы это делалось само:

```powershell
cd D:\warehouse_project\deploy\windows
.\НАСТРОИТЬ-СНЯТИЕ-РЕЗЕРВА.ps1
```

Задание работает раз в час. Права администратора не нужны.

Посмотреть, что было бы отменено сейчас, ничего не меняя:

```powershell
venv\Scripts\python.exe manage.py expireorders --dry-run
```

Подтверждённые заказы не трогаются никогда: за ними стоит
договорённость с покупателем.

### Если впереди стоит nginx

Тогда все запросы приходят с адреса самого nginx, и предел по адресу
перестаёт различать покупателей. Настоящий адрес приходит в заголовке
`X-Forwarded-For`; чтобы система ему поверила, впишите в `.env`:

```
TRUST_FORWARDED_FOR=True
```

**Только при nginx впереди.** Без него этот заголовок подделывается
кем угодно, и предел обходится одной строкой в запросе.

## Документы для бухгалтерии

Система выставляет четыре документа в Excel: счёт на оплату, товарную
накладную ТОРГ-12, универсальный передаточный документ (УПД) и акт
сверки взаимных расчётов.

### Что заполнить перед первым документом

**Реквизиты организации** — один раз. Откройте `/admin/`, раздел
«Реквизиты организации», и внесите: ИНН, КПП, юридический адрес, банк,
БИК, расчётный счёт, руководителя и главного бухгалтера. Там же
выбирается ставка НДС и то, включён ли налог в цену.

Запись предполагается одна: это сведения о предприятии, а не
справочник. Вторую завести нельзя — иначе документы печатались бы
разными реквизитами в зависимости от того, какая нашлась первой.

Проверить, заполнены ли они, можно обычной проверкой:

```powershell
python manage.py checksetup
```

**Покупателей-организаций** — по мере надобности. Заказы с витрины
приходят от частных лиц: там есть имя, телефон и адрес, но нет ИНН.
Счёт такому покупателю выписать можно и так, а накладную или УПД
организации — уже нет. Карточка заводится в разделе «Покупатели-
организации» панели управления и привязывается к заказу.

### Где брать документы

| Документ | Откуда | Когда доступен |
|---|---|---|
| Счёт на оплату | Заказы, кнопка «Счёт» | по любому заказу, кроме отменённого |
| ТОРГ-12 | Заказы, кнопка «Накладная» | после отгрузки |
| УПД | Заказы, кнопка «УПД» | после отгрузки |
| Акт сверки | Отчёты, вкладка «Акт сверки» | по организации за период |

Накладная и УПД появляются только после отгрузки намеренно: до неё
товар не передан, и подписывать передачу нечего.

### Оплаты

Акт сверки показывает отгрузки и оплаты. Отгрузки система знает сама,
а оплаты вносятся вручную: в панели управления, раздел «Оплаты» —
заказ, сумма, дата и номер платёжного поручения. Без них акт покажет
одни отгрузки и вечно растущий долг.

### Что считается само

Сумма прописью и НДС считаются системой. Налог по умолчанию
выделяется из цены (20/120), а не начисляется сверху: на витрине цена
конечная, налог сидит внутри неё. Если цены в договорах указаны без
налога, снимите в реквизитах галочку «Цены указаны с НДС».

Суммы округляются построчно, а итог складывается из округлённых строк —
как в бухгалтерских программах. В обратном порядке итог местами
расходился бы со суммой строк на копейку, и документ выглядел бы
ошибочным.

## Переход на PostgreSQL

Система работает на SQLite — базе в одном файле, без отдельного сервера.
Для двух-трёх сотрудников это правильный выбор: ничего не нужно
устанавливать и обслуживать.

### Когда переходить, а когда не нужно

Проверено замером на этой самой системе (три сотрудника строят отчёты,
четвёртый в это время проводит документы, пять секунд работы):

| | Документов проведено | Самый долгий отчёт |
|---|---|---|
| SQLite как было | 2434 | 2,24 с |
| SQLite сейчас (режим WAL) | 7157 | 0,02 с |

Замедляло работу не число сотрудников само по себе, а то, что отчёт
держал базу и проведение документа ждало его окончания. Это уже
исправлено настройкой: база работает в режиме WAL, где читающий и
пишущий не мешают друг другу. Отдельно ставить PostgreSQL ради
скорости на нынешних объёмах смысла нет — на замере она оказалась
даже медленнее SQLite.

Переходить стоит, когда:

- **база должна лежать не на том компьютере, где работают.** Режим WAL
  не работает на сетевой папке, а SQLite на общем диске — верный путь к
  повреждённой базе;
- **сотрудников становится больше десятка**, и они работают
  одновременно;
- **нужны средства обслуживания PostgreSQL**: копии без остановки,
  подключение резервного сервера, разграничение доступа на уровне базы.

### Как перейти

Порядок проверен целиком, с настоящими данными.

**1. Поставьте PostgreSQL** с postgresql.org (подойдёт версия 14 и
новее). При установке запомните пароль пользователя `postgres`.

**2. Заведите базу и пользователя.** В «SQL Shell (psql)»:

```sql
CREATE USER warehouse_user WITH PASSWORD 'придумайте-пароль';
CREATE DATABASE warehouse_db OWNER warehouse_user;
```

**3. Снимите копию** — до всякого переноса:

```powershell
python manage.py backup --to D:\Копии\Склад
```

**4. Впишите в `.env` доступ к новой базе:**

```
DB_ENGINE=postgres
DB_NAME=warehouse_db
DB_USER=warehouse_user
DB_PASSWORD=придумайте-пароль
DB_HOST=localhost
DB_PORT=5432
```

**5. Создайте таблицы и перенесите данные:**

```powershell
python manage.py migrate
python manage.py topostgres
```

Команда переносит всё: справочники, документы, движения, заказы,
журнал действий, учётные записи сотрудников вместе с паролями. В конце
она сверяет число записей в каждой таблице с прежней базой и, если
что-то не сойдётся, отменяет перенос целиком — полупереехавшая база
хуже непереехавшей.

Отдельно она переставляет счётчики номеров. Это то место, где обычный
способ переноса (`dumpdata` / `loaddata`) подводит молча: данные
выглядят перенесёнными, а первый же новый документ падает с ошибкой
«такой номер уже есть», и обнаруживается это через день, у кладовщика.

**6. Проверьте, не удаляя прежнюю базу:**

```powershell
python manage.py checksetup
```

и откройте пару рабочих страниц — остатки, приход, отчёты. Файл
`db.sqlite3` оставьте на месте хотя бы на неделю: вернуться к нему
можно в любой момент, поставив в `.env` обратно `DB_ENGINE=sqlite`.

### Резервные копии после перехода

Команда `backup` работает и с PostgreSQL — ничего перенастраивать не
нужно, задание в планировщике продолжит работать как прежде. Копия
снимается программой `pg_dump` и так же проверяется сверкой числа
записей.

Одно условие: `pg_dump` должен быть доступен по PATH. Он входит в
поставку PostgreSQL; если сервер стоит на другом компьютере, поставьте
на этот клиентские программы PostgreSQL той же версии. Без него команда
скажет об этом прямо, а не сделает вид, что копия снята.

Восстановление из такой копии описано в файле `ЧТО-ЭТО.txt` внутри
самой копии.

## Частые проблемы на Windows

### «python: command not found» / «не является внутренней командой»

Python не в PATH. Варианты:
1. Переустановите Python, отметив «Add python.exe to PATH».
2. Или используйте лаунчер: `py -3 manage.py runserver` вместо `python manage.py runserver`.
3. Или укажите полный путь: `C:\Users\ИмяПользователя\AppData\Local\Programs\Python\Python311\python.exe`

### Ошибка выполнения `.ps1` скриптов

```
File ...\Activate.ps1 cannot be loaded because running scripts is
disabled on this system.
```

Решение (один раз для текущего пользователя, без прав администратора):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### «Файл update.ps1 не имеет цифровой подписи»

```
Не удается загрузить файл ...\update.ps1. Файл не имеет цифровой подписи.
Невозможно выполнить сценарий в указанной системе.
```

Речь про политику `AllSigned` — она требует подписи у любого сценария,
включая написанные на месте. Её часто ставит системный администратор, и
тогда `Set-ExecutionPolicy` для своего пользователя её не перебьёт:
машинная политика главнее пользовательской.

Обходить её целиком не нужно. Запускайте обновление через
`ОБНОВИТЬ.bat` — он снимает ограничение только для одного запуска
одного файла, ничего не меняя в системе. Или то же самое вручную:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\update.ps1
```

Какая политика действует и откуда она взялась, покажет:

```powershell
Get-ExecutionPolicy -List
```

Если в строке `MachinePolicy` или `UserPolicy` стоит `AllSigned`, она
задана групповой политикой — снять её может только администратор.

### `pip install` зависает или выдаёт ошибку сборки (building wheel)

Обычно на Windows все пакеты проекта ставятся из готовых `.whl`-файлов
без компиляции. Если всё же ошибка — обновите pip и setuptools:

```powershell
python -m pip install --upgrade pip setuptools wheel
pip install -r requirements.txt
```

### Порт 8000 занят

```powershell
# Узнать, какой процесс занял порт
netstat -ano | findstr :8000

# Завершить процесс по PID (последнее число в строке выше)
taskkill /PID <номер> /F

# Или просто запустить на другом порту
python manage.py runserver 8001
```

### Путь к проекту слишком длинный (MAX_PATH)

Редко, но возможно при глубокой вложенности папок — Windows по умолчанию
ограничивает пути 260 символами. Распаковывайте архив ближе к корню диска,
например в `C:\projects\warehouse_project`, а не в глубоко вложенные
папки типа `C:\Users\Имя\Documents\Работа\Проекты\2026\Складской учёт\...`.

### Кириллица отображается «кракозябрами» в консоли

Если PowerShell показывает вместо русских букв нечитаемые символы:

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
chcp 65001
```

Выполните обе команды перед запуском `python manage.py runserver`.

### Антивирус блокирует venv или медленно устанавливает зависимости

Некоторые антивирусы (включая Windows Defender) сканируют каждый файл
виртуального окружения при создании, что может занять 1-2 минуты — это
нормально, просто подождите. Если совсем не отвечает — добавьте папку
проекта в исключения антивируса.
